# 许愿之后 · 万圣节活动包

将 `obsession-halloween-package.zip` 上传至管理员「新建活动 → 导入活动包」，不必填写手工字段。活动编号为 `obsession-halloween-2026`，新活动默认未开放。也可从已有活动的「活动包管理」导入，此时保留已有活动编号与开放状态。

内含 3 个分类、每类 4 枚成就，共 12 枚。名称、任务和章节为根据提供的故事简介原创的校园鬼屋互动设计，不代表电影的正式剧情细节。

| 分类 | 成就（建议二维码放置点） |
| --- | --- |
| 未说出口的爱 | 夜访者（入口）、未寄出的信（信件布景）、镜中疑影（镜面布景）、愿望的门槛（许愿区入口） |
| 许愿柳的代价 | 柳下见证（许愿柳）、仅此一愿（许愿互动）、红线缠身（红线布景）、代价显形（第二章终点） |
| 逃离执念 | 回声之后（方向提示）、松开红线（选择互动）、最后一道门（出口）、把自己还给黎明（纪念区） |

现场点位是设计建议，可在后台修改任务描述以匹配实际布置。默认每枚领取上限 100 人，不是活动总人数上限。时间暂写「时间待公布」，正式开放前请调整。

页面通过平台 SDK 获取真实成就、解锁状态和抽奖状态。活动包内不再提供网页摄像头入口；参与者使用手机系统相机扫描现场二维码。每枚成就需分别扫码，最后一枚也是终点扫码，不会自动因集齐而解锁。

页面包含完整设计的“终局抽签”和“我的奖品”内页，可在主题页面中查看奖品、参与资格、库存、抽奖结果和中奖编号。抽取动作仍由平台后台完成在线校验。导入活动包后，需在管理员后台创建抽奖项目，选择参与所需成就，并配置奖品、库存和中奖概率；未创建抽奖项目时，页面会显示“抽奖项目尚未开放”。

导入后在「成就管理」查看、下载二维码，再打印贴到对应点位。二维码应从最终部署网址生成，包中未预设学校服务器地址。网页实时摄像头需要 HTTPS，手机系统相机可直接扫描能访问的 HTTP/HTTPS 领取链接。

ZIP 中的 festival-config.json 含二维码领取识别码，仅供管理员导入，不要将 ZIP 分发给参与者。平台会将配置入库，并且不把该配置文件发布为静态页面。

素材使用 CSS 绘制的柳枝、系统字体与 Emoji，无需加载外部图片、字体或电影海报。源文件在同名目录内，可继续修改设计；修改后需重新打包，确保 manifest.json、festival-config.json 和 index.html 位于 ZIP 根目录。
